# obot.agent v0.5.0 (Upcoming)

- **The check that keeps every surface on one stylesheet now runs when nobody types it.** The style census was written, tested and documented, and then nothing ever called it — no workflow, no sweep, no script — so the requirement's promise that "a check fails if any surface reintroduces its own copy" described a check that could only fail if somebody happened to run it by hand. It has two callers now, doing the two different jobs the two vantage points allow. CI runs it on every pull request and blocks the merge, seeing this repository alone. The five-minute sweep runs it across all nine declared roots — the only place on any machine where the hub, `safety.viz`, `open.gismo` and `open.csr` sit together — and reports onto the Operations Dashboard without blocking anything. Neither could do the other's job: CI cannot see a public site drift, and the sweep cannot stop the pull request that drifts it. Watched failing and passing in both, including the workflow's own command line executed by a test. The costs are stated rather than assumed: 0.4 seconds inside a sweep that takes half a minute, bounded by a real timeout rather than by a measurement that was true once.

- **A green tick no longer gets to mean "clean" when it means "I could not look".** The CI runner has one clone, so four of the nine roots are invisible to it and always will be — an absent clone is nobody's defect to fix, and a check that goes red for an unfixable reason is a check somebody switches off. So it passes, and the run's summary page opens with the sentence that says what the pass covers: "Clean for what could be read. 7 declared roots and 8 registered claims were not on this machine and went unexamined — unknown, not clean", followed by all fifteen of them by name. The sweep says the same thing without raising an alarm about it, and does raise one when the census could not run at all. There is a subtlety underneath that had to be measured rather than reasoned about: GitHub's default shell for a workflow step has no `pipefail`, so publishing the verdict through a pipe would have thrown away the census's exit code and rendered a red census as a green tick. The step names its shell, and a test asserts it.

- **And the first honest run found something, which is what a first honest run is for.** A hub file added after the shared sheet landed declares six colours of its own and is registered nowhere. It has not been registered, excused or baselined away — an exemption written to make a first run green is how a gate becomes inert a second time — so the style suite is red about it on any machine with the hub cloned, and green on the runner where the hub is absent. That gap is the same blindness the callers were built to remove, one layer up, and it is now visible instead of assumed away.

- **What the sweep knows about a decision artifact's premises now reaches the artifact.** The five-minute claim sweep has re-checked 31 premises across seven decision pages since #262 and said `PREMISE BROKEN` on the Navigator surface when one expired — and the page itself said nothing, so anyone opening it met an argument built on a premise that might have gone stale with no sign anything had ever looked. `tools/premise-status` hands the hub what was measured (an id, a fingerprint, one of three states, a time — no sentences), the hub renders it above every artifact's masthead, and the sweep reports the distance between what it measured and what the published pages actually carry. It never writes during a sweep — that file is tracked in a clone the sweep also fast-forwards, and a dirty tree stops the fast-forward — so the comparison happens in memory against the copy committed on `main`, and landing a new reading stays an act that ends in a commit ([jwildfire/obot.roadmap#266](https://github.com/jwildfire/obot.roadmap/issues/266)).

- **Every config item now opens by telling you what problem it fixes, instead of what to type.** The card and the list entry both lead with a plain sentence about what stays broken if you never do it — "Your GitHub history goes on recording structural edits you never made", "Every hub edit an agent makes goes through a shell workaround that mangles content" — and the command comes after it. All seven open items were rewritten this way, and the field is required from now on: an item nobody can write that sentence for is a candidate for not being needed, which is half of what the field is for. It is checked as well as required, so a "why" that is really a command, a path, a flag or a bare mechanism is refused at capture with every reason at once rather than quietly accepted.

- **An open decision now has a podcast episode you can answer from the car, and it stays that way without anybody remembering.** Every five minutes the sweep asks whether each open decision artifact has a current episode, and reports the ones that do not — the same kind of standing condition as a closed requirement with no closure summary, rather than a batch somebody runs when they think of it. Two were owed tonight and both are on the show: **branch protections** (four minutes, one question, three options) and the **safety census rebuild** (five and a half, six questions, and it says out loud why it is over five). The three episodes from 18 August are recorded too, so the check counts what already exists instead of asking for it again.

- **An episode can no longer outlive the page it was made from.** Each record carries a fingerprint of its artifact as spoken — the page with the markup taken off — so restyling a page changes nothing and a reworded sentence marks the episode stale, which is a gap the sweep reports. When that happens the shipped episode stays up, because you may already have heard it, and the fresh one opens with a correction you can hear that names what changed. That is the same rule the pages already follow, said in the one format where you cannot look at the original.

- **A five-minute episode is 880 words, not 750.** The words-per-minute figure this repo used to size scripts was 150, with a comment saying it had been measured on the published episodes. It had not been: those episodes read at 170 to 185 words a minute. The guideline you set was being enforced at about four minutes of audio, so writers were cutting material out of episodes that were already inside it. The number is now the measured one, the renderer prints the real rate every time it runs, and a test fails if the constant drifts outside what the published episodes actually did.

- **The audio renderer is in the repository now.** The script that turns an episode into the file Spotify gets lived in one job's scratch directory and nowhere else, one cleanup away from having to be reinvented. It is `tools/voice/render.py`, same voice and same pacing as the episodes you have already heard, and the brief beside it carries every trap the first run paid for — including the retry that published two duplicate episodes.

- **A warning on the sweep page that could never turn red now can.** "Voice receipt failed" was worded exactly right for the alarm check and indented by two spaces, which files it as a footnote to the line above and strips its alarm entirely. It rendered grey for as long as it existed, and its test asserted the wording rather than the placement, so the test stayed green.

- **A review of the car-voice lane found four ways it could have answered the wrong decision, or published one of your answers. All four are closed.** The lane shipped disarmed, so none of them reached you — but each was reproduced on the live queue before being fixed, and each is now a test named after the sentence that broke it. **"No, two weeks is plenty"** was filed as an answer to decision number two, at full confidence: `no` was being read as a position marker, and it is the most common first word of a dictated answer. **"Number one priority: leave branch protections alone"** was filed against decision one while naming decision two by its published name — the position was consulted before the name was even scored; a position and a name that disagree are now the ambiguous case, not a race the position wins. **A name whose first word is an ordinary word** — "note format", "decision log" — could never be answered at all, because that first word was being stripped as filler along with "obot" and "hey"; it now survives whenever it is the first word of an open decision's name, and the sentence the episode tells you to say routes. And **a queue of eleven or more** had no word for the eleventh position, so "number eleven" was not a position at all and the sentence went to the ideas board.

- **An answer now has to have been said AFTER the list it answers.** The five-minute poll re-reads every uncompleted item on the Reminders list and deliberately leaves ideas alone for the lane that files them — and nothing on this machine drains that lane, so ideas sit there. Reproduced: an idea about the car-voice lane sat for two days, a decision named "car voice" was then published, and the next sweep recorded your *question* as your *answer* to it, stamped it and completed it. Every other guard in the matcher reasons about one sentence against one queue at one instant; nothing bounded how old the sentence was, and the sweep supplied unlimited retries. Reminders carry a creation date, so that is the bound now: anything older than the queue you were last read is left exactly as it is and counted on the page, and a machine that has never read you a queue answers nothing at all.

- **And a sentence about a decision you answered yesterday is kept, not published.** With nothing open, a sentence naming a decision was not an answer to anything, fell through to "idea", and was posted to the public discussions board and completed — while the narration had just promised you that anything unmatched "stays on the list, so you will see it did not land". That is the likeliest moment for it to happen: a correction, minutes after your last answer was applied. Decisions decided in the last three weeks are now matched too, and naming one is UNROUTED with the date it was decided, never an idea. A registry whose shape has changed is a failed read rather than "he has decided everything", and a machine that cannot read the decision list now leaves the whole list alone instead of branding every note on it unroutable.

- **And the lane that files the list stopped being able to post as you.** The token guard lived in a shell function called as `GH_TOKEN="$(token)"`, so its refusal killed the *subshell*, left the variable empty, and `gh` read an empty token as no token at all and fell back to your own keyring — which would have recorded the post as yours, permanently, for the third time this month. It is minted in the shell that posts now, checked there, and a run that could not mint exits non-zero instead of looking like a quiet one. The same run also stopped truncating you: it split the Reminders list by line, and `read` stops at a newline, so a note whose second line held the actual answer was cut off — both in what the guard was shown and in what was published. It reads by record now, and a note with no trailing separator (which is every one-item list) is no longer dropped entirely.

- **The receipts and the readings stopped lying in three smaller ways.** A rename or a completion that failed was discarded, and those two writes are the whole mechanism that stops an item being read again — a failed one is now reported as an alarm rather than repeating silently every five minutes. The unrouted store's read flag was thrown away before rendering, so a directory that could not be opened produced the same line as a clean lane: a positive claim about your sentences made from a failed read. And `private:` was enforced by two rules that disagreed about case and whitespace — "Private: …" missed the branch that wrote the file, reached the router, and was counted as "1 kept private" while nothing was kept anywhere and the reminder was never completed. There is one rule now, it lives with the routing, and it refuses to write a private note into a git checkout at all.

- **You can answer an open decision from the car now, out loud, with no screen and no number to remember.** You said it twice: you listen to these driving, you might dictate a reply, and you will not have a GitHub issue number in your head. Until now the only way to answer a decision was to reach a keyboard, so a decision you had actually made stayed open until you got to one. Two halves close that. `voice-decisions script` renders every open decision as speech — named the way a person names it ("branch protections", never `D0022` and never a slug or a date), its choices stated so they can be said back, and the last thing you hear is exactly what to say. It writes the queue snapshot as it goes, which is the point: the moment the words are read out is the moment they become the vocabulary, so there is no second list to keep in sync — a test takes the example sentence the script reads out, hands it to the router unchanged, and requires it to land on the decision it was read out for. Coming back, you dictate into the same Apple Reminders list Siri has always been able to reach hands-free, and what you said becomes an ordinary record in the same store the dashboard writes to, with your words verbatim and the channel on the record. Everything already built around that store therefore covers a car answer for free: the Navigator announces it within five minutes, and the answered-but-unapplied detection flags it if nobody acts. ([roadmap #265](https://github.com/jwildfire/obot.roadmap/issues/265))

- **And when it cannot tell which decision you meant, it says so instead of picking one.** The two ways this fails are not equally bad and the whole design turns on that. A sentence that reaches no decision costs you one repeat. A sentence filed against the *wrong* decision costs the decision: your words land on a page you were not talking about, nothing looks wrong from any surface — the store shows an answer, the sweep announces it, an agent applies it — and the decision you were actually answering is still open with nothing on it. So every close call is refused and refusing is loud. Two open decisions that fit what you said equally well return neither, named. A handle the vocabulary already knows sounds like another one is never resolved by score at all, and the episode tells you to say the number instead. "Number two" resolves only against the list you were actually read: if a decision has been answered or published since, the position no longer names what it named then, and it is refused with that reason rather than resolved against a list that moved. Saying "answer" first declares one, and a declared answer that matches nothing can never fall through to the ideas queue — it is kept whole as UNROUTED, because that is a loss and not an idea. Matching is deliberately loose otherwise: "branch protection" answers "branch protections", because a name you have to say perfectly is a name you cannot use at seventy miles an hour.

- **The confirmation is the reminder itself, so it needs no screen either.** A receipt you have to open something to read is not a receipt for someone driving. So the note you dictated becomes its own: one that reached a decision is stamped with which one and completed, so the list empties — asking Siri what is on your obot list and hearing nothing IS the confirmation. One that reached no decision is stamped with the reason and **left there**, because completing it would remove the only evidence you have that it failed, and you cannot be asked to repeat a sentence you do not know went missing. Nothing new is ever added to that list; it is your voice-note inbox and stamping a note you wrote is a different thing from filing into it.

- **The lane that files that list to a public board now asks first, and fails closed.** `reminders-to-ideas` has posted everything on the `obot` list to the hub's Ideas discussions since July — and from now on some of what is on that list is a decision of yours, which is local-only by construction. Every item is offered to the router first and only what comes back as an idea is posted. If the router cannot be run at all, the item is left pending rather than posted: failing closed costs a re-run, failing open publishes your decision. The suite runs the real script against a stubbed Reminders and a stubbed `gh` and asserts on what `gh` was and was not asked to do, because a grep for the guard would pass whether or not the guard works. The bot token is minted lazily and checked non-empty as well, so a sweep in which everything you said was a decision reaches for no GitHub token at all.

- **And nothing has ever polled that list, which the sweep now says out loud.** No LaunchAgent, no cron, and the idea fold skips it on purpose because `osascript` can stall on a permission prompt — so the channel this was all built on was one nothing listened to. The five-minute sweep is now the listener, with that objection answered rather than argued with: one runner, a hard timeout, and a failure that comes back as a failed read instead of an empty inbox. The automation grant is yours to give, though, so it stays **off until armed** — `voice-decisions arm` — and the Navigator's own section says which of the three states it is in on every pass: not armed and why that matters, armed and read, or armed and unreadable, which is an alarm the page can actually render. A section that is silent when nothing was said and silent when nothing is listening would hide the failure that costs the most.

- **What the fleet spends is now measured before it is spent, and the cap you set is enforced by something other than an agent remembering it.** On 18 August you said "no more than fifty percent of my weekly usage in any given night" — and nothing on this machine could have obeyed it, because nothing knew what the week had cost. Fifteen workers ran overnight and neither they nor the lead that dispatched them could have said how much of your allowance had gone. The measurement, it turns out, already existed: `build_usage_data.py` has priced this machine's transcripts since July. What did not exist was anything that ran it — the session wrapup was its only heartbeat, the wrapup stopped when the model became a standing prime session, and the artifact sat five days old while the week's allowance went in five nights. The five-minute sweep is now that heartbeat, rebuilding the priced artifact every ten minutes into its own cache — never into the hub clone, because a dirty tree is what makes the sweep's own checkout update refuse. Your position sits at the very top of the Navigator's state file, above both ledgers, which is where the ops tab reads from and what a dispatching agent reads first: what tonight has cost, what the week has cost, and how much is left. ([roadmap #275](https://github.com/jwildfire/obot.roadmap/issues/275))

- **And the cap is expressed in your unit, not in a number anybody guessed.** "Fifty percent of my weekly usage" needed a denominator, and the honest one was sitting on the machine: `~/.claude.json` caches Anthropic's own meter, which reports the weekly bucket as a **percentage** with a reset instant. Every dollar field on it is null and Anthropic publishes no numeric weekly limit for Max, so any dollar allowance stated as fact would have been fabricated — and the cap is therefore counted in percentage points, with no denominator to invent. Dollars become points through one dated calibration, re-derived whenever the meter refreshes, which is what lets it survive the +50% promotional limits expiring on 31 August. The ladder is graduated and it is the *week* that bites rather than any one night: it warns once a full night's cap no longer fits in what remains, and stops when the night has spent its headroom or the week has passed 90% — the point at which you actually called a halt. Rehearsed against the week that ran out, it warns on the 17th, cuts off the night of the 18th at roughly $968 of the $1,167 that night actually took, and refuses on the 19th, which is the morning you stopped everything by hand. Three lanes enforce it: `obot-auto` refuses to launch, `worker-id claim` refuses to issue an id — so no sibling spawn that follows the contract gets past it — and the sweep writes `.claude/autonomy-halt`, the switch the fold and obot-auto already honour, lifting it again on its own when the week resets. A reading that did not happen is `unknown` with its own exit code and refuses too; a broken measurement is not permission to spend. The Navigator, prime and the admiral are never gated, because blinding the surfaces that report the spend would be the worst possible way to control it. Full account in [`docs/spend-cap.md`](docs/spend-cap.md).

- **What comes next is written down, and it ages where you can see it.** Sixty-odd open requirements and no statement of what came next: every dispatch was chosen by whoever was awake, from whatever had most recently been discussed — which works while a person is watching and stops the moment a clock is running. The next ten now sit at the bottom of your queue, in order, each with the one line saying why it is where it is, because a rank you cannot interrogate is one you cannot steer. It sits *under* your three buckets and asks you for nothing; the moment it demanded an action it would be a fourth obligation, so a test asserts the absence of the ask rather than trusting anyone to remember. Rank is the only thing declared — the order and the reason, in `rank/top10.json` and nowhere else. The title, whether it is still open, its milestone, whether it is blocked and how far its sub-issues have got all come from GitHub at read time, keyed off the `top10` label you asked for, so the one API call and the panel can never tell you different things. And it ages in two places rather than one: "Ranked 2026-08-19, 3d old" is the order, "state refreshed 4m ago" is everything beside it, and a refresh that failed says so in its own sentence with the age of what is actually on screen. An age nothing could measure prints as "not known" and never as a zero — the order's age comes from the commit that last touched the file, not from its mtime, which a fresh clone stamps with the moment it was written. ([roadmap #278](https://github.com/jwildfire/obot.roadmap/issues/278))

- **And nobody has to remember that a slot opened.** When one of the ten finishes, the next is promoted — a rule that rots inside a fortnight done by hand, as every hand-maintained list here has. A `top10` label on a closed issue is a computed condition, so the five-minute sweep reports it: which rank opened, which issue closed, and how many issues the `on-deck` bench holds. It stops exactly there. Choosing the replacement is strategy and belongs to 🎩🤖 obot-prime, so the bench reaches the section as a *count* and never as a list — a containment in the shape of the data rather than in anyone's restraint — and nothing about a slot ever reaches your config list. Three of the first ten closed within a day of the label being created, and all three took the label with them on the way out; the reader now asks GitHub about a ranked issue the label query cannot see, so a finished requirement shows as the open slot it is instead of vanishing from the head entirely.

- **A pull request only you can merge now puts itself on your config list, and the admiral stops shouting about it.** Your queue holds three buckets — release candidates, decisions, config items — and a pull request touching a guardrail path belongs squarely in the third: it is unmergeable by every agent and nothing but your keyboard clears it. Nothing put it there. c0016 covers obot.agent#198 because a person noticed and filed it by hand, and on a night nobody was looking that pull request would have sat unrouted — not a release candidate, so never in your review queue, and unmergeable, so never cleared. It is a computed condition, not something to notice: `obot-merge --check` already prints that a carve-out path was touched and that the lane it forced admits no agent, so the five-minute sweep now reads that output and raises the item, carrying the pull request, the paths it touches, the issues it closes and the merge command with your approval flag. Nothing is ever raised twice — coverage is matched on the pull request itself rather than on the headline, so a retitled pull request still does not duplicate, and the second run raises nothing and claims no id. The critical tag stays earned: the raise passes the issues the pull request closes and GitHub is asked whether they are open. And ⚓🤖 obot-admiral, which was escalating #198 once a cycle as unmergeable by any agent, can now see the item and stops — an escalation that repeats and cannot be acted on is how an escalation channel gets ignored, which costs more than the one pull request. The section says which pull request it stopped escalating and under which id, by number and id only, and an unreadable config list suppresses nothing and says so. ([#264](https://github.com/jwildfire/obot.agent/issues/264), [roadmap #220](https://github.com/jwildfire/obot.roadmap/issues/220))

- **Watching the dashboard for a change to appear was what stopped the change appearing.** The five-minute sweep restarts the Operations Dashboard onto new code, and it held that restart off whenever the page had been requested recently — a poll, a monitor, or you refreshing while you waited for a merge to land. The wait had no end: for as long as anything kept looking, the restart kept not happening. On the morning of 18 August the checkout stood at `7482007` while the server served `0832443`, so a config page that had been merged and pulled answered 404 to the only person waiting to read it, and the sweep reported the deferral honestly every five minutes the whole time. The wait now ends. Three deferrals is the ceiling — a quarter of an hour — after which the restart goes ahead whether anybody is reading or not, because a dropped request announces itself and a refresh repairs it, while a page that renders perfectly and is out of date is not visible as a fault at all. The bar it waits on changed too: only a request actually in flight can be killed by a restart, and the rendered pages fetch nothing else from this machine, so "somebody loaded a page twelve seconds ago" was never evidence that a restart would interrupt anything. What is left of it is two seconds, because a click is two requests. The line on the page carries the count now — `deferral 2 of 3 — after that it restarts regardless` — instead of promising a restart "once nobody is reading it", which is a promise the person reading it makes false. ([#258](https://github.com/jwildfire/obot.agent/issues/258), [roadmap #243](https://github.com/jwildfire/obot.roadmap/issues/243))

- **And the check that says the restart worked now checks the right thing.** It used to end on the first answer from port 7326, which proves something is serving and not that the replacement is: the process being replaced answers that question perfectly well, so a replacement that never started would have been reported as a success. It now compares the process id and the commit the server reports against the replacement it just started, and a replacement that never took the port is stopped rather than left running. The old fallback that fetched the page itself is gone, for a second reason worth stating: fetching the page is real traffic, it resets the very clock the deferral reads, and a verification that did that seeded the next deferral it was verifying its way out of.

- **The morning brief is one paragraph and a list, and a test counts them.** You asked for a daily executive summary in a specific shape — one short paragraph about progress, then your todo list, one line per bullet — and that is now what the 07:00 fold writes, to `.claude/fold/brief.md`, with `--brief` rendering exactly what the next fold would write. The paragraph says what landed overnight and what that leaves waiting on you, in at most sixty words; the list is your queue in the order you set on 15 August — release candidates, then decisions, then a config count — one line each, with the link at the end. Everything else that a daily output has ever grown is gone rather than compressed: no headings, no meta line, no session-report link, no footer, no coda. The bounds are the point. One paragraph and one line per item are countable, so the suite counts them on the real output and on adversarial input, and the fold refuses to write a brief that fails its own check — the openclaw summaries this replaces grew from 136 words to 865 against a template nobody was measuring. The diary entry is untouched: it is the archive, written for someone who was not present, and the brief is the twenty seconds you spend on a phone. The config line names the items that have earned the critical tag by id — `3 critical config items (c0016, c0017, c0019) and 10 others` — using the same rule the dashboard uses, so c0017, the item gating the fold's own schedule, is no longer invisible in the brief that would tell you about it; ids only, never item text, and anything that is not exactly `cNNNN` is dropped rather than repaired. And nothing in it is composed out of failed queries: a git scan that could not run says so rather than becoming "nothing landed overnight", a partial one states its number as a floor, and `--brief` on a queue nobody could read prints nothing at all. ([#252](https://github.com/jwildfire/obot.agent/issues/252), [#255](https://github.com/jwildfire/obot.agent/issues/255), [roadmap #238](https://github.com/jwildfire/obot.roadmap/issues/238))

- **Agent commits have been going out under thirty-eight different wrong identities, and every one of them looked right.** The bot's commit address ends in a nine-digit user id, and until now every tool and every session typed that number itself. Counting every commit in the seven active checkouts found 1,068 on the correct address, 101 on a legacy form that also works — and 301 on thirty-eight distinct fabrications, one of them reading `223456789`, twenty-six of them belonging to real GitHub accounts. A wrong id still renders `obotclaw[bot]` in `git log` and in the GitHub UI, so the failure is invisible in exactly the place you would go to check it. The reassuring half, verified rather than assumed: GitHub matches the whole address, so those commits link to nobody at all — they are unattributable, not credited to a stranger. The id now lives in one module and is never typed; the fold's own publisher, which was hardcoding a real user's id on every diary commit, takes it from there. ([#241](https://github.com/jwildfire/obot.agent/issues/241), [roadmap #260](https://github.com/jwildfire/obot.roadmap/issues/260))

- **The commit-identity scan no longer has a way to read a commit it could not parse as a clean one.** Two doors, both the same shape: a record that came back short defaulted its trailer fields to empty, which made the commit look like nobody's agent work and dropped it out of the scan without a trace; and because the subject sat in the middle of the record, a commit subject containing the field separator shifted every field after it and landed the `Worker:` trailer in the wrong slot. Either one turns a failed read into a clean verdict. The subject is last now, so it can hold whatever it holds, and a record that does not parse is counted and reported under the broken headline instead of skipped. Found by 👯🤖 W0059 naming the shape from a bug of its own the same night, not by a test. ([#247](https://github.com/jwildfire/obot.agent/issues/247))

- **The five-minute sweep now says when an agent commit is wearing the wrong name.** A commit carrying a `Co-Authored-By: Claude …` or `Worker:` trailer whose author does not link to the bot is provably agent work mis-attributed — and because you never write those trailers, the check cannot fire on your own commits. It reads all seven checkouts, reports when clean, says which checkouts it could not read rather than counting them as clean, and caps its list with the number it did not show. 110 commits are currently recorded under your name that agents wrote; 87 more are yours.

- **A push wrapper, because no token was ever going to fix the push.** Every remote here is SSH, so `git push` authenticates with your key whatever token is in the environment — that is how two force-pushes and a branch deletion were recorded as yours inside one three-hour window. `scripts/obot-push` mints an app token and pushes over HTTPS as the bot, refuses outright when the mint returns nothing rather than falling back to your keyring, refuses a remote outside your org, and refuses `--force` and `--delete`. Your SSH remotes are untouched, so your own pushes stay yours. Its first real use found a defect in itself, which is now a test: `git push -u <url>` records the URL it was handed as the branch's remote, so passing the flag through would have written a live token into `.git/config` — the wrapper now sets the tracking branch against the remote's name instead.

- **Two workers finished work you had already granted the lane for, and held it for your approval anyway — because the file they read told them to.** `AGENTS.md` is loaded into every session here, and on the subject of merging it framed the command with "Once a merge is approved" and never said what the default was. `scripts/policy.json` has said the opposite since July: all seven repos in it are `profile: auto`, so each one's integration branch merges with no flag, no wait and nothing in your queue. Neither worker misread anything; one of them would have left a published page telling you something false for a day and a half. The file now leads with the default and names the exceptions — a release-role branch, a pull request touching a guardrail path, and a repo not in the file at all, which is refused rather than held. Vocabulary is now fixed: the **dashboard** is this local page, the **hub** is the public site. ([roadmap #180](https://github.com/jwildfire/obot.roadmap/issues/180))

- **Blockers now have a ten-second capture path.** When an agent hits a wall only @jwildfire's hands can clear — a settings line the permission classifier refuses, an account-level grant, a device-side setup — `tools/blocker-log` files it to the workspace-local blockers list in one allowlistable call: headline, a required paste-ready fix, required provenance, optional what-it-unblocks. The script creates the list (sentinel first) if missing, refuses duplicate headlines, and inserts under the list's `## Open` heading without ever rewriting the shared file. Approved with the blockers-list decision (BL3, 2026-08-15); the list itself stays local-only — the hub deploy now fails if its sentinel ever reaches the published site.

- **A reply now comes before the work that supports it.** After obot-prime answered one question in 31 silent minutes (bookkeeping, a long sibling briefing, and a post-spawn wrap-up all composed ahead of the reply), the responsiveness contract gained a mechanical turn-ordering rule: the first content block of any turn answering @jwildfire is text, a delegating turn's first tool call is the spawn, and all bookkeeping follows the reply. Prime additionally caps every turn at two tool calls before its first visible text, defers memory and state writes to after the ack, and composes briefings as pointers to on-disk artifacts rather than paraphrases. Briefing depth is unchanged — only its position in the turn moved. ([#102](https://github.com/jwildfire/obot.agent/issues/102))

- **Every repo's write policy now says whether it is operational or clinical.** The control split @jwildfire set — operational repos self-improve with automatic merges to production, clinical repos are reviewed by him before anything reaches the released surface — is recorded as a `class` field on each repo in `policy.json`, printed by `obot-policy explain` and `matrix`, and checked by `validate`. demo-301 is classified clinical on his override, with the condition for a later switch to operational written where the next session will find it. The retired safety-histogram fork (archived; its renderer lives on in safety.viz) leaves the policy file in the same change. ([decision](https://jwildfire.github.io/obot.roadmap/reports/decisions/2026-08-15-operational-clinical-classification/))

- **Testing the dashboard can no longer take your status-line link away.** The little file that says *the dashboard is up, on this port* was a global claim any server could take, and on 2026-08-16 five of them did — every one an agent running a second instance to test a change to the dashboard, which is exactly what it should have been doing. Each took the claim on the way in and deleted it on the way out, so your link pointed at a test server, and then at nothing, for about half an hour while your real dashboard kept serving perfectly. Nothing warned, because nothing could: a marker left behind by a server that stopped looks exactly like a healthy one. The fix removes the failure rather than detecting it — a server started on a port other than the dashboard's own is a test server, and a test server never claims the marker. Nor does one that asked for the dashboard's port and had to settle for the next, because something else already owns that address. Behind those, two rules for the cases nobody plans for: a live claim is never overwritten, and an instance removes only the claim it wrote — same process *and* same port, because process numbers get reused and an exit that checks only the number deletes what it never wrote. Ask `node obot.agent/tools/serve-marker` what the marker says and it answers `live`, `stale`, `unreadable` or `none` rather than handing back a URL that no longer answers. Proved by running it: a second dashboard started on 7399 beside your own on 7326, announcing what it was not doing, then killed — your marker byte-identical through both. ([#142](https://github.com/jwildfire/obot.agent/issues/142))

- **Two finished pull requests sat unmerged overnight because of how the merge command was typed.** Three workers in two days reported the same thing — the merge lane refuses background agents — and it was the wrong diagnosis twice over: nothing refuses them, and nothing is background-specific. The workspace allowlist permits three spellings of `obot-merge`, and a permission rule matches a command only when every sub-command matches, splitting on `|`, `&&` and `;`. Agents habitually write `bash scripts/obot-merge 158 -R jwildfire/obot.agent 2>&1 | tail -20`, where the `bash` prefix defeats all three path rules and `tail -20` is a second sub-command no rule covers. Unmatched commands do not fail — they fall through to the auto-mode classifier, which is nondeterministic and refuses about one call in thirty. The evidence is a census rather than a theory: of 497 `obot-merge` invocations in the session transcripts, exactly 7 were written in a matchable form and all 7 were allowed, while every one of the 17 refusals in that history sits among the 490 that matched nothing. The same string that was refused on obot.roadmap#217 was allowed three minutes later, which is what a coin flip looks like from the inside and why three separate workers each concluded they had hit a wall. The fix changes no permission surface and needed nobody's approval: the documented form is now the bare single command everywhere an agent reads it, `session-reviews` no longer tells the reviewer to chain the merge call into a compound, and a test fails if any documented example drifts back to a decorated shape. ([#162](https://github.com/jwildfire/obot.agent/issues/162))

# obot.agent v0.4.0

**See it move:** the [annotated v0.4.0 demo](https://jwildfire.github.io/obot.roadmap/reports/oa-v0.4-demo/) walks each change as a real terminal capture with the command that produced it.

v0.3.0 gave obot the ability to run unattended. v0.4.0 is about what that run costs you: a session opens before the model thinks, the dashboard is one click from any status line, write policy is one file instead of two drifting ones, the three things that used to park an overnight run on a permission prompt are fixed, and the release you are reading has a written contract behind it. Nothing in the session-command surface is removed or renamed.

## What's new

- **A session opens before the model produces a token.** The hand-off — the previous session's priorities, what is waiting on you, what changed overnight — is assembled by a shell script during command expansion, so it is already in the prompt at first paint instead of being rediscovered over several model round trips. `/session-init` and `/s-init` are now the same fast command, and `obot-auto` launches unattended leads through it too. ([#76](https://github.com/jwildfire/obot.agent/pull/76), [#77](https://github.com/jwildfire/obot.agent/pull/77), [#80](https://github.com/jwildfire/obot.agent/pull/80), [#81](https://github.com/jwildfire/obot.agent/pull/81) · hub [#91](https://github.com/jwildfire/obot.roadmap/issues/91), [#148](https://github.com/jwildfire/obot.roadmap/issues/148))

- **Every status line ends with a clickable hub link** — the live session ops hub inside the obot workspace, the deployed roadmap hub anywhere else — so the dashboard is one click from any session. The status line also became a tracked, installable artifact under `tools/statusline/` rather than one untracked file on one machine, and the watch loop can serve the live view over loopback so the link opens in Chrome instead of Finder. ([#52](https://github.com/jwildfire/obot.agent/pull/52) · hub [#24](https://github.com/jwildfire/obot.roadmap/issues/24))

- **A repo's write policy is one decision in one file.** Merge tiers and unattended-autonomy grants used to live in two files needing separate edits per repo, and they had drifted into a state neither could express. They are now one `policy.json` where a repo gets a single profile, `obot-policy explain <repo>` prints what that profile means in plain words, and branches match by role rather than by name — so a release branch called `master` or `site` needs no special-casing. ([#59](https://github.com/jwildfire/obot.agent/pull/59), [#61](https://github.com/jwildfire/obot.agent/pull/61) · hub [#18](https://github.com/jwildfire/obot.roadmap/issues/18), [#140](https://github.com/jwildfire/obot.roadmap/issues/140))

- **Overnight runs stop parking on permission prompts.** Spawned agents were handed a worktree path outside `.claude/worktrees/` — the only location Claude Code auto-approves — so each one waited for a click that, unattended, means until morning. A new triage table also tells you in one command why a session is missing from Remote Control, and the wrapup rebuilds the Analytics cost data before it posts so the spend page stops going stale. ([#69](https://github.com/jwildfire/obot.agent/pull/69), [#63](https://github.com/jwildfire/obot.agent/pull/63), [#67](https://github.com/jwildfire/obot.agent/pull/67) · hub [#18](https://github.com/jwildfire/obot.roadmap/issues/18), [#46](https://github.com/jwildfire/obot.roadmap/issues/46))

- **What needs you is the first thing a wrapup says.** Every wrapup output — checkpoint page, diary entry, morning digest, closing message — now opens with the release candidates awaiting review and the decisions awaiting your call, each linking its PR and its demo or decision artifact, with the work log underneath. Both lists carry forward until you close them, decisions post to the hub's Q&A discussions where you answer in-thread, and a risk named in a wrapup becomes a tracked issue carrying a proposed mitigation. ([#83](https://github.com/jwildfire/obot.agent/pull/83), [#85](https://github.com/jwildfire/obot.agent/pull/85), [#71](https://github.com/jwildfire/obot.agent/pull/71), [#72](https://github.com/jwildfire/obot.agent/pull/72) · hub [#142](https://github.com/jwildfire/obot.roadmap/issues/142)–[#144](https://github.com/jwildfire/obot.roadmap/issues/144), [#148](https://github.com/jwildfire/obot.roadmap/issues/148))

- **Releases now have a written contract.** `docs/rc-framework.md` states what reaches your review queue — release candidates and decision artifacts, nothing else — and what a candidate must carry, with a deployed demo page as a hard gate. The companion `rc-release-notes` skill puts the notes in a repo's `NEWS.md`, demo link first, and the tag publishes that section verbatim on approval. This file is that convention applied to obot.agent itself. ([#83](https://github.com/jwildfire/obot.agent/pull/83), [#86](https://github.com/jwildfire/obot.agent/pull/86) · hub [#123](https://github.com/jwildfire/obot.roadmap/issues/123))

- **Releases are now real, reviewable PRs.** A lagging `stable` branch, cut at v0.3.0, gives this repo what it never had: a base to propose a release against. Each release is a `main → stable` PR whose diff is exactly the release window, carrying the RC roles and merging only with explicit approval — the release you are reading arrives that way. The same decision set the program's governing principle (operational repos self-improve with automatic merges to `main` and periodic `stable` releases; user-facing clinical work is reviewed before prod) and the NEWS.md convention this heading follows: every repo keeps a NEWS.md current in `main`, unreleased work under a `(Upcoming)` heading. ([decision record](https://github.com/jwildfire/obot.roadmap/discussions/155))

- **The test suite runs in CI.** Every push and pull request now runs the full 112-test suite plus the policy-file validator on GitHub Actions — previously this repo had no CI at all, which mattered rather a lot for a repo whose merges to production are automatic. A red check now blocks a broken `main` instead of a morning surprise.

- **Prime remembers across restarts.** The standing Q&A session writes its durable state to a capped, provenance-stamped `prime-state.md`, and a cold session rehydrates from one read via `tools/prime-rehydrate` — including across midnight, which the first version got wrong and a same-night fix corrected. ([#91](https://github.com/jwildfire/obot.agent/pull/91), [#94](https://github.com/jwildfire/obot.agent/pull/94) · hub [#154](https://github.com/jwildfire/obot.roadmap/discussions/154))

- **`/grill-me` interviews you about a goal** — a resumable, multi-session elicitation interview that extracts what you want built, including the parts held tacitly, before requirements are filed. ([#96](https://github.com/jwildfire/obot.agent/pull/96))

- **Thirteen session commands have one-word aliases, and three are new:** `/s-idea` files a half-formed thought to the triage queue without derailing the session, `/s-reviews` walks the PRs waiting on a decision one at a time, and `/s-prime` runs a session as the standing question desk — a long-lived session that answers from warm context in seconds and delegates anything slower. ([#64](https://github.com/jwildfire/obot.agent/pull/64), [#84](https://github.com/jwildfire/obot.agent/pull/84) · hub [#48](https://github.com/jwildfire/obot.roadmap/issues/48), [#114](https://github.com/jwildfire/obot.roadmap/issues/114))

## Also in this release

- The roadmap audit queue costs no tokens until you click, and batches submit in parallel with per-agent worktrees so concurrent applies stop colliding. ([#55](https://github.com/jwildfire/obot.agent/pull/55), [#56](https://github.com/jwildfire/obot.agent/pull/56) · hub [#92](https://github.com/jwildfire/obot.roadmap/issues/92), [#109](https://github.com/jwildfire/obot.roadmap/issues/109))

Re-verified against current upstream on 2026-08-14; they stay drafts because agents do not write outside the `jwildfire` org. ([#62](https://github.com/jwildfire/obot.agent/pull/62))
- **Milestones stopped being optional.** No work starts on an issue until it carries a milestone, and a release names the issues it ships — `obot-merge` now refuses any merge whose `Closes` target has no milestone, and a release-branch merge whose body names no issue at all. The rule is written where an agent hits it before branching: `--auto` increment selection, the release-notes procedure and the RC checklist. safety.viz v1.6.0 shipped the night before this landed grouping none of the four issues it delivered. ([#89](https://github.com/jwildfire/obot.agent/issues/89) · hub [#123](https://github.com/jwildfire/obot.roadmap/issues/123))

- **A note on the merge lane.** Three `obot-merge` calls in this window were denied by the Claude Code auto-mode classifier and succeeded on a plain retry, which briefly looked like a threat to the whole unattended model. It was not: 3 denials in 99 real invocations, traced to the one command spelling the workspace permission allowlist did not cover. The allowlist rule landed on 2026-08-14 and the three merges that closed this release went through on the first attempt. Evidence and reasoning: [decision artifact](https://jwildfire.github.io/obot.roadmap/reports/decisions/2026-08-14-merge-lane-classifier-denials/).
